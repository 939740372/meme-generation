# 需求规范：同名导出自动顺延序号不覆盖 (auto-numbered-export)

- 状态：researching
- Feature slug：auto-numbered-export
- 分支：feature/auto-numbered-export
- 负责人：Meme Studio Team
- 日期：2026-10-22

## 1. 业务范围

支持用户在导出 GIF/WebP/AVIF/MP4 时，即使指定路径的文件已经存在于本地磁盘中，也能够正常点击导出并成功生成新文件，同时完整保留旧文件。新文件自动在主文件名后面追加系统规范的圆括号序号（如 ` (1)`, ` (2)` 等）。

## 2. 用户故事

- 作为创作者，当我对同一个视频片段尝试不同文字或画风特效并多次导出时，我希望应用不会弹窗报错“文件已存在”，而是自动为我生成保留所有版本的新文件（如 `cat (1).gif`），这样我能随时对比多个效果，也不会误覆盖旧文件；
- 作为创作者，如果我在导出路径中手动输入了一个已经带序号的文件名（如 `my-meme (1).mp4`），再次导出时我希望它自动变为 `my-meme (2).mp4`，而不是丑陋地追加为 `my-meme (1) (1).mp4`；
- 作为批量导出使用者，当队列中有多个片段导向相同文件名时，我希望它们能按照系统序号规则顺序保存，两两独立，完整保留。

## 3. 功能需求

1. **自动不覆盖顺延命名 (FR-01)**：
   - 当调用 `render_gif` 且 `plan.output_path` 指向的文件在本地磁盘已存在时，系统必须自动寻找首个未被占用的序号文件路径；
   - 命名格式必须遵循操作系统标准规则：`<stem> (<N>).<ext>`，例如 `output.gif` -> `output (1).gif`；
   - 若 `output (1).gif` 亦存在，则顺延至 `output (2).gif`，依此类推。
2. **已带序号智能识别 (FR-02)**：
   - 若原文件名本身已带有 ` (<N>)` 形式的序号后缀（例如 `test (3).webp`），系统应提取基础名 `test`，从 `N+1`（即 `4`）开始递增探测（生成 `test (4).webp`），禁止生成双层嵌套括号。
3. **取消硬拦截错误 (FR-03)**：
   - 彻底废除原先的 `OUTPUT_EXISTS` 报错拦截，确保用户发起导出流程零阻碍。
4. **前端状态与历史记录同步 (FR-04)**：
   - 导出完成后，前端工作区当前路径自动更新为实际生成的序号文件路径，方便用户直观看到生成结果；
   - 导出历史记录列表中准确记录并展示实际生成的新文件路径与字节大小；
   - 「在访达/资源管理器中显示」和「复制文件」必须对应到新生成的序号文件。
5. **批量队列规则统一 (FR-05)**：
   - 批量导出辅助模块 `generateQueueOutputPath` 调整重名判定模式，使用标准的带空格圆括号 ` (<N>)`，与单片导出行为保持一致。

## 4. 非功能需求

1. **安全性与无静默覆盖 (NFR-01)**：
   - FFmpeg 执行参数中必须继续带有 `-n`，即便在极低概率的并发竞态下，也坚决不允许发生已有文件被静默覆盖；
2. **性能与零额外依赖 (NFR-02)**：
   - 路径检测完全基于 Rust 原生 `Path::exists()`，无额外三方 crate 依赖，检测在毫秒级内完成（<= 5ms）；
   - 设置最大重试上限（10,000 次），避免异常死循环；
3. **跨平台兼容 (NFR-03)**：
   - 支持 macOS（Unix 风格斜杠）与 Windows（反斜杠及盘符路径），正确处理无扩展名或多点号（如 `video.draft.1.gif`）的边界情况。

## 5. 验收标准

- [ ] 本地磁盘不存在同名文件时，正常按原名导出；
- [ ] 本地磁盘已存在同名文件（如 `a.gif`）时，点击导出成功生成 `a (1).gif`，原 `a.gif` 完整保留；
- [ ] 连续再次点击导出，继续生成 `a (2).gif`，历史记录中同时显示全部生成物；
- [ ] 对已有序号文件名（如 `clip (2).mp4`）导出时，自动顺延为 `clip (3).mp4`；
- [ ] 单测与类型检查全部通过（含 Rust 路径算法单元测试和 `pnpm build`）。
