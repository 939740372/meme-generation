# 需求调研：批量处理与导出任务队列 (batch-queue)

- 状态：merged
- Feature slug: batch-queue
- 分支：feature/batch-queue
- 负责人：Antigravity

## 1. 背景与核心痛点

Meme Studio 目前具备了从视频中精准截取、裁切、叠加多段文字与贴纸并导出 GIF/WebP 的完整能力。然而，高产创作者与表情包二创博主在日常使用中面临一个突出瓶颈：
1. **单任务导出必须等待**：每次点击导出后，应用进入 `rendering` 状态并独占界面，用户无法继续调整进度条去截取视频中的下一个精彩名场面；
2. **多片段产出效率低**：从一部 10 分钟影视片段或动漫中切出 5~10 个表情包是常态，每次导出需要 3~10 秒。重复多次“截取-等待-导出-截取-等待”打断了创作的心流；
3. **输出重命名冲突易覆盖**：用户若截取多个片段而忘记手动修改输出文件名，会导致后一次导出覆盖前一次成果，造成数据丢失。

## 2. 竞品与业界方案调研

| 软件/工具 | 队列机制 | 调度与并发 | 冲突与重命名处理 |
|----------|---------|-----------|-----------------|
| Adobe Media Encoder | 独立的 Render Queue 渲染列表 | 顺序调度执行，单任务独占 CPU/GPU 资源以防系统卡死 | 自动追加序列编号 `_001`, `_002` |
| HandBrake (开源转码器) | 顶栏显著的 "Add to Queue" 与 "Start Queue" | 队列顺序转码，单任务失败不影响后续任务继续转码 | 目标目录统一设定，文件名依片名/预设模版生成 |
| 剪映 / Final Cut Pro | 后台导出任务队列抽屉，悬浮进度条 | 后台非阻塞队列渲染，前台可继续剪辑 | 自动生成唯一文件名防冲突 |

## 3. 技术约束与决策依据

1. **并发策略：单任务依序执行 (Sequential Execution)**
   - FFmpeg 调色板渲染与转码本身为高度 CPU/多线程密集型计算（尤其是 GIF 的 `palettegen` + `sierra2_4a` 双阶段算法）；
   - 若盲目并发开启多个 FFmpeg 进程，会导致 CPU 抢占、风扇狂转、系统界面掉帧甚至内存暴涨；
   - 决策：采用顺序调度执行（FIFO 队列），同一时刻仅运行 1 个活跃 FFmpeg 渲染任务，其余排队等待，保证系统流畅与转码稳定性。
2. **状态机与重试设计**：
   - 队列任务生命周期：`pending`（排队中） $\to$ `rendering`（渲染中） $\to$ `completed`（已完成） / `failed`（失败） / `cancelled`（已取消）；
   - 容错策略：队列中某一个任务因源文件损坏等原因失败时，不中断整个队列，标记该任务为失败并自动继续处理下一个任务，支持对失败任务单项“重试”；
   - 支持“暂停/停止队列”与“一键清空完成项”。
3. **文件名自动生成与目录策略**：
   - 当点击“加入导出队列”时，自动根据源文件名、起始秒数或序号生成防覆盖的文件名（例如 `movie_01.2s_to_03.5s.gif` 或 `movie_01.gif`）；
   - 输出路径若冲突自动追加递增后缀，彻底规避文件覆盖。
4. **抽屉与视口约束**：
   - 队列面板整合至底部抽屉的第 4 个 Tab：“📋 导出队列 (N)”；
   - 底部操作栏左侧增加显眼的“＋ 加入队列”按钮与“🚀 批量导出”按钮，不增加额外固定面板高度，维持 `1280 × 820` 视口零多余滚动条。
