# 需求调研：带音轨的短视频表情导出 (audio-video-export)

- 状态：merged
- Feature slug: audio-video-export
- 分支：feature/audio-video-export
- 负责人：Antigravity
- 日期：2026-10-22

## 1. 背景与痛点

1. **声音是现代表情与名场面的灵魂**：
   - 很多流传极广的影视台词、鬼畜神曲与网红对白，单纯看文字或静音动图时表现力大打折扣（例如经典咆哮、魔性笑声、特色方言对白等）；
   - 现今各大社交平台（微信会话窗口短视频、小红书、抖音、B站动态、微博）均全面支持或优先推荐 3~5 秒超短视频；微信对话框发送短视频时支持一键自动循环并播放声音。
2. **当前应用能力的局限**：
   - 当前 Meme Studio 支持 GIF、WebP、AVIF 三种动图格式，渲染参数统一硬编码为 `-an`（静音/剥离音轨）；
   - 创作者如果截取了带声音的台词片段并配上台词字幕与贴纸，无法直接导出一份带声音的微视频，必须转移到剪映、PR 等大型剪辑软件重新打字幕和压制，违背了“本地优先、轻快极速”的表情包创作初衷。

## 2. 调研结论与技术选型

| 调研项 | 方案对比 | 决策依据 |
|--------|----------|----------|
| 封装格式选型 | MP4 (`.mp4`) vs WebM (`.webm`) | **优先 MP4 (H.264/AAC)**：MP4 在 iOS 微信、Android 各大社交 App、macOS 访达及 Windows 上的硬件解码兼容率接近 100%，WebM 在苹果生态与部分移动端社交 App 中兼容性不佳 |
| 视频编码器 | `libx264` (`yuv420p`, `-crf 23`, `-preset medium`) | FFmpeg sidecar 内置支持，压缩比与编码速度达到最优平衡，`-movflags +faststart` 将 moov atom 置于头部实现瞬间秒开与边下边播 |
| 音频编码器与容错 | `aac` (`-b:a 128k`) 配合 `-map 0:v -map "0:a?"` | 原生内置 AAC 编码器；使用 `0:a?` 可选映射：**源视频有音轨时自动混流编码，源视频无音轨时安全跳过而不报错**，防止任务因无音轨而崩溃 |
| 画面尺寸偶数约束 | `yuv420p` 要求长宽为偶数 | 现有的 `scale=w:-2:flags=lanczos` 已经自动保证高度为偶数（`-2` 表示自动计算且强制对齐为 2 的倍数），天然兼容 `libx264` |
| 音效与变速联动 | 画面加速/慢放/倒放时音频同步 | 2x 加速挂载 `-af atempo=2.0`，0.5x 慢放挂载 `-af atempo=0.5`，物理倒放挂载 `-af areverse`；保持声画同步魔性效果 |

## 3. 风险与未知项

- **部分输入源视频缺少音轨 (No audio stream)**：
  - 若直接使用 `-map 0:a`，FFmpeg 在遇到无声视频时会抛出 `Stream map '0:a' matches no streams` 致命错误；
  - 解决方案：在参数中传递 `-map "0:a?"`（FFmpeg 语法：尾随 `?` 表示可选流匹配），完美兼容有声和无声素材。
- **倒放滤镜音频缓冲**：
  - `areverse` 与 `reverse` 一样需要把样本暂存到内存，针对表情包 0.5s~5s 的截取场景，开销微秒级，完全可控。
