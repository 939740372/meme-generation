# 需求调研：可视化时间轴与画布拖拽创作工作区

- 状态：merged
- Feature slug：creative-timeline-canvas
- 分支：feature/creative-timeline-canvas
- 负责人：待定
- 日期：2026-10-22

## 1. 背景和问题

Meme Studio 已经完成了底层的媒体处理、Sidecar 二进制分发、调色板优化与中英文 `drawtext` 文字渲染能力。但当前的交互仍停留在“纯表单输入”模式：
- **时间截取不够直观**：用户必须手动输入“开始 · 秒”与“结束 · 秒”，无法感知整段视频的时间跨度和当前所选片段在视频中的相对位置；
- **元素排版缺乏所见即所得（WYSIWYG）**：文字和 PNG 贴图的摆放位置依赖手动输入 `X` 和 `Y` 像素坐标，用户需要反复尝试猜测坐标值才能摆到合适位置。

这与桌面端专业创作工具（如剪映、Photoshop、Kapwing）的体验存在较大差距。用户需要更自然、更直观的可视化时间轴与画布交互。

## 2. 用户和场景

- **场景 1：精准截取名场面**：用户导入一个 30 秒的搞笑视频，在时间轴上通过左右手柄快速滑动定位到 3.5s ~ 6.2s，时间轴中间高亮选区并实时显示选中时长（2.70 秒）。
- **场景 2：画面排版与加梗**：用户输入“这就离谱”，直接在中央预览画布上用鼠标拖动文字到人物头顶或画面底部；导入 PNG 贴图后直接拖动到指定角落，控制面板的数值随拖拽实时变化。

## 3. 现有方案调研

- **时间轴组件设计**：
  - 双滑块轨道（Dual-thumb Range Slider / Timeline Track）：轨道代表视频总时长（0 到 `media.durationSecs`），左手柄代表 `startSecs`，右手柄代表 `endSecs`，中间为选区高亮色块。
  - 手柄支持鼠标拖拽，防止两滑块交叉（保持 `startSecs < endSecs`，最小间隔如 0.1s）。
- **画布拖拽映射设计**：
  - 画布在不同屏幕分辨率或固定视口下，显示尺寸（CSS 像素）与视频原始尺寸（如 1920×1080）通常存在缩放比例（`scale = displayedWidth / originalWidth`）；
  - 必须进行坐标映射换算：`originalX = Math.round(cssX / scale)`，`originalY = Math.round(cssY / scale)`，保证无论画布缩放到多大，导出的最终 FFmpeg 坐标都是精准的视频物理像素。
  - 拖拽元素需提供视觉指示器（选中态边框、抓取光标 `cursor: grab / grabbing`）。

## 4. 技术调研与约束

1. **响应式与固定视口**：
   - 保持应用 `1280×820` 固定视口无外层滚动条的桌面级设计；
   - 时间轴需紧凑嵌入在预览区下方或控制面板顶部，不挤占底部状态栏。
2. **纯前端交互无性能损耗**：
   - 拖拽过程基于原生 PointerEvent / MouseEvent 或 Vue 响应式状态，保持 60fps 流畅度，无不必要的 Rust IPC 调用；
   - 最终提交转码时依旧复用标准可序列化的 `RenderPlan`。

## 5. 已确认事实

- 视频总时长由 `media.durationSecs` 提供。
- FFmpeg 端文字与图案坐标均为绝对物理像素值。
- 坐标必须限制在画面边界内，不得出现负值或超出边界。

## 6. 当前假设

- 用户通过画布拖拽文字和贴图能满足绝大多数表情包排版需求，无需复杂的第三方庞大富文本画布库（如 Fabric.js），轻量原生实现可保证零额外依赖和最佳性能。

## 7. 调研结论和决策

| 结论/决策 | 理由 | 影响 |
| --- | --- | --- |
| 原生双滑块时间轴 | 零外部依赖，交互顺手，无体积开销 | 需编写双轨计算逻辑与防交叉约束 |
| 画布交互图层（Overlay Canvas） | 直接在原预览画面上叠加绝对定位的拖拽手柄 | 提升排版效率，达到所见即所得 |
| 坐标比例映射计算 | 保证 UI 缩放与 FFmpeg 物理像素一致 | 拖拽时换算，保持 RenderPlan 契约不变 |
