# 需求调研：可视化矩形裁切框与画布交互

## 1. 背景和问题

在当前的视频到 GIF 制作流程中，用户若想对视频画面进行画面构图裁切（例如只保留人脸表情、去除画面上下黑边或多余杂物）：
1. **纯数字输入痛点**：目前“裁切”功能仅提供 X、Y、W、H 四个数字输入框，用户必须靠心算和多次盲试才能定位大致坐标；
2. **缺乏视觉反馈**：用户在编辑时无法在中央画布上直接观察到裁切框的具体覆盖区域以及裁切后的保留范围；
3. **构图缺乏参考线**：在制作正方形或焦点特写表情包时，没有九宫格三分线等常用构图辅助线，容易裁偏。

## 2. 用户和场景

- **场景 1：特写人脸表情包制作**
  用户导入了一段横屏（1920×1080）电影片段，只想截取主角的搞怪脸部。勾选「裁切」后，中央画布立即出现半透明遮罩与可交互的九宫格裁切框，用户直接按住裁切框中心拖拽到人脸位置，并拉动手柄缩放至合适大小，右侧 X/Y/W/H 数值实时联动，所见即所得。
- **场景 2：精准比例快捷裁剪（1:1 正方形 / 居中满幅）**
  用户希望制作标准的 1:1 微信正方形表情包，点击预置的「1:1」或「居中」快捷按钮，裁切选框立即按黄金居中位置贴合，用户可在画布上再做微调。
- **场景 3：参数面板与画布双向同步**
  用户在参数面板精细修改 X 或 W 数值时，画布上的裁切矩形框与遮罩实时跟随重绘；在画布上拖拽缩放时，面板上的输入框数值以整数像素精确同步。

## 3. 现有技术调研与方案对比

### 3.1 遮罩渲染方案对比
1. **SVG Mask / ClipPath 方案**：
   - 优点：标准矢量遮罩，支持任意路径。
   - 缺点：DOM 结构稍繁琐，缩放时存在微弱的重绘开销。
2. **CSS 巨型投影方案 (`box-shadow: 0 0 0 9999px rgba(0, 0, 0, 0.6)`)**：
   - 优点：性能极高，纯 GPU 合成，无需额外计算复杂多边形路径；外层容器配合 `overflow: hidden`，天然对选框外部区域形成均匀的半透明暗色遮罩；
   - 决策：采用 CSS box-shadow 方案作为主遮罩，渲染轻量、性能极佳。

### 3.2 手柄与九宫格交互设计
- **九宫格辅助线**：裁切框内部通过绝对定位渲染 2 条横线（33.3%, 66.7%）和 2 条竖线（33.3%, 66.7%），采用淡金色微透亮线，构图参考清晰且不遮挡画面细节；
- **8 方向调节手柄**：
  - 4 个角柄：NW（左上）、NE（右上）、SW（左下）、SE（右下）
  - 4 个边柄：N（上）、S（下）、W（左）、E（右）
  - 中心区域：支持自由平移拖拽，光标为 `move`；
  - 各手柄光标分别对应 `nwse-resize`、`nesw-resize`、`ns-resize`、`ew-resize`。
- **坐标映射机制**：
  - 视频绝对像素尺寸：$W_{media} \times H_{media}$
  - 画布视口展示尺寸：$W_{stage} \times H_{stage}$
  - 转换缩放比率：$s_x = W_{stage} / W_{media}$，$s_y = H_{stage} / H_{media}$
  - 交互过程中所有移动增量 $(\Delta x, \Delta y)$ 在 PointerMove 中通过逆比例换算回源视频坐标系，并进行四舍五入与边界约束 $[0, W_{media}]$，保证 FFmpeg crop 滤镜参数的绝对精准。

## 4. 调研结论和决策

| 结论/决策 | 理由 | 影响 |
| --- | --- | --- |
| 引入中央画布九宫格交互式裁切框 | 彻底告别盲输 X/Y/W/H 四个数字的原始交互 | 大幅提升构图效率与表情包制作体验 |
| 采用 CSS 阴影遮罩 + 8 手柄微操体系 | 极高性能、响应灵敏，无复杂依赖 | 拖拽过程 60 FPS 丝滑顺畅 |
| 与参数面板保持无损双向响应式联动 | 兼顾鼠标直觉调整与键盘精准微调 | 满足所有层次用户习惯 |
| 增加「居中」、「铺满」、「1:1」等快捷构图辅助按钮 | 针对微信表情与常见短视频构图快速排版 | 减少拉伸拖拽重复步骤 |
