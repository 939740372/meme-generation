# 需求调研：文字描边与字幕底色条增强

- 状态：merged
- Feature slug: text-styling-stroke
- 分支：feature/text-styling-stroke
- 负责人：待定
- 日期：2026-10-22

## 1. 背景和问题

在 Meme/GIF 创作中，文字是表情包传达幽默与台词信息的最核心要素。然而在当前版本中：
1. **对比度缺失痛点**：文字仅提供单一的“字号”与“前景色”。如果视频背景是亮白色（如户外、强光镜头），白字会彻底融进背景无法辨认；如果背景是深黑色，黑字同样无法辨析；
2. **缺乏经典表情包质感**：绝大多数风靡全网的 Meme（如经典黑底白字、Impact 字体、大字报）其视觉精髓正是**“黑边白字”粗描边**；
3. **缺少台词字幕条模式**：影视截剧中常使用的“半透明黑底字幕条”目前无法自定义开启与调整透明度（之前在底层代码中硬编码了灰暗背景），无法适配多样化的字幕风格。

## 2. 用户和场景

- **场景 1：经典黑边白字表情包（描边强化）**
  用户截取了某影视名场面，文字内容为“你不要过来啊”，选择白字，开启描边（宽度 2~3px，黑色）。无论背景如何剧烈变化，文字边缘均有清晰轮廓，视觉冲击力极强。
- **场景 2：影视台词字幕条（半透明背景框）**
  用户制作经典电影台词动图，选择开启字幕底框，底色设为深黑，透明度设为 0.65，文字呈现专业院线电影的半透明黑底字幕质感。
- **场景 3：纯净文字无底框**
  用户制作极简艺术动图，关闭背景底框，文字只保留纯色或微描边，画面干净清爽。

## 3. 技术调研与对比

### 3.1 FFmpeg drawtext 滤镜能力调研
验证表明 Martin Riedl 静态编译带 `libfreetype` 的 FFmpeg 支持如下关键属性：
1. **描边 (Stroke/Border)**：
   - `borderw=N`：描边像素宽度（0~12）；
   - `bordercolor=COLOR`：描边颜色（支持 `0xRRGGBB` 或 `black` 等）；
2. **背景框 (Box)**：
   - `box=1` 或 `box=0`：是否绘制背景底框；
   - `boxcolor=COLOR@OPACITY`：底框颜色与不透明度（例如 `0x000000@0.65`）；
   - `boxborderw=P`：底框内边距 Padding（建议 6~8 像素）。

### 3.2 Web 预览与 FFmpeg 渲染的一致性
- **CSS 描边还原**：
  - `-webkit-text-stroke: {width}px {color}`；
  - 配合 `paint-order: stroke fill`，保证描边绘制在文字主体后方，避免大宽度描边蚕食文字内白；
- **CSS 底框还原**：
  - 当 `useBox` 开启时，`background-color: rgba(R, G, B, A)`，配以内边距 `padding: 4px 8px; border-radius: 4px`；
  - 当 `useBox` 关闭时，`background-color: transparent`。
- **参数映射**：
  - 颜色统一采用 Hex `#RRGGBB`；
  - 透明度以百分比/浮点数联动，两端呈现达到 99% 的视觉一致性。

## 4. 调研结论和决策

| 结论/决策 | 理由 | 影响 |
| --- | --- | --- |
| 拓展 `TextOverlay` 数据模型 | 增量增加可选描边与底框字段，保持向前兼容 | 旧草稿与历史记录零破坏 |
| 取消底层硬编码的 `box=1` | 赋予用户完全自主权（可关闭、可自定义透明度） | 满足纯字与台词条多样诉求 |
| 画布所见即所得 CSS 映射 | 采用 `-webkit-text-stroke` 与 `paint-order` | 编辑时预览即为导出最终效果 |
| 控制面板分层折叠与紧凑排版 | 兼顾功能丰富与 1280×820 固定视口约束 | 无滚动条，布局优雅 |
